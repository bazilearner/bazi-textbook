# 万年历 · 晚子时换日规则（子时日柱归属）

> 本文件补 `judgment-core.md` 第七节的不足。晚子时（23:00–01:00）出生的**日柱归属**是八字排盘最常见、也最易被忽略的歧义源。本技能曾因未显式处理此点而整盘判错，特此立规。

---

## 〇、本技能的**默认立场**（用户已明示，优先于一切）

> **「一天没有两个子时。如果有第二个子时，那就是进入了第二天。」**

据此直接得出**默认裁决**：

| 出生时刻（真太阳时校正后） | 判定 | 日柱 |
|---|---|---|
| 23:00—24:00（晚子时） | **已过 23:00，属「第二个子时」** | **归次日** |
| 00:00—01:00（早子时） | 次日的第一个子时 | 次日（同日柱，自洽） |

**这条准则的意义**：它把「两派并存」的悬置问题**一次性消解**了——
23:55 与次日 00:10 本属**同一个子时**，故日柱**必须相同**。这是准则的自洽性验证：
用「次日日期」排盘与用「次日 00:10」排盘，日柱必然一致。

**因此本技能的默认流程不再是「双盘并出」，而是「按准则一次排准」**——
除非用户另行指定另一派。（见第五节：若非用户明确要求，**不要再写双盘对照**，
那只会让读者得不出结论。）

### 落地操作（两步，不再双排）

```bash
# 出生日为 D，时刻在 23:00—24:00
# ① 判：已过 23:00 → 日柱归 D+1
# ② 排：用「D+1 的日期 + 00:10」排盘 —— 这才是正确的一张盘
$N paipan.js chart "<D+1 的日期> 00:10" 1

# ⚠ 千万不要用「D+1 的日期 + 原时刻」！那样时干会再多进一位：
#   例：D=08-20 23:55 → 归次日须用 08-21 00:10，得「甲申 甲子」；
#   若误用 08-21 23:55，则得「甲申 丙子」——而甲日子时必是甲子，丙子只配乙/庚日。
#   这是「日主与时干不匹配」的错盘，但日柱本身是对的，所以只比日柱查不出来。
#   唯一可靠的复核是：把整盘逐字对一遍（含时柱）。
```

**示例（虚构）**（某造生于 `1995-08-20 23:55`，真太阳时校正后仍在子时）：
- 若按「晚子时算当日」（`paipan.js` / `lunar-typescript` 的默认）→ 日柱 **癸未**、时柱甲子。
- 按本技能准则「归次日」：**用「次日 00:10」排盘** → 四柱 `乙亥 甲申 甲申 甲子`，日柱 **甲申**。
- **对照错法**：若误用「次日 + 原时刻」（`1995-08-21 23:55`）→ 得 `乙亥 甲申 甲申 丙子`。
  **日柱虽同为甲申，时柱却变成丙子**——而甲日子时必为 **甲子**，`丙子` 只配乙/庚日。
  这是「日主与时干不匹配」的错盘，且**只比日柱查不出来**（故复核须逐字对整盘）。
- 两派日主 **癸 ↔ 甲** 互异；时干由日干起，故时柱、调候主神、用神、相神随之而变
  —— 故这一处**必须裁准**，不能含糊。
（复算：`paipan.js chart "1995-08-20 23:55" 1` 与 `paipan.js chart "1995-08-21 00:10" 1`；
再跑一次 `chart "1995-08-21 23:55" 1` 亲眼看一下那个错的时柱。）

## 一、两派的由来（保留备查，但**默认已由第〇节裁决**）

子时跨 23:00–01:00，横跨两个公历日。日柱到底按哪一天取，存在两派：

| 流派 | 日界位置 | 23:00–24:00 日柱 | 00:00–01:00 日柱 | 典型归属 |
|---|---|---|---|---|
| **流派一 · 晚子时算当日**（日界在 00:00 / 子正） | 午夜 0 点 | **当日**日柱 | 次日日柱 | 多数现代排盘软件、`lunar-typescript` 默认、`paipan.js` 默认 |
| **流派二 · 晚子时归次日**（日界在 23:00 / 子初） | 晚 11 点 | **次日**日柱 | 次日日柱 | 紫微斗数派、**本技能默认（见第〇节之准则）** |

> ⚠️ **注意**：`paipan.js` 的**默认**行为是流派一（因底层 `lunar-typescript` 如此）。
> **按本技能立场，晚子时命例必须显式用「次日日期」排盘**，不可直接采用脚本默认结果。
> 这是最容易出错的一步——脚本默认与技能立场不一致。

**日主之差会改写**：羊刃有无、冲刑组合、十神六亲、神煞、地势、旬空、
**以及时柱、调候主神有无、用神相神、大运干支**——**不是小修，是整盘重推**。

## 二、与「真太阳时」的底层关系（西部城市为何特别棘手）

严格子平要求用**真太阳时**定昼夜与日界，而日界应在「真太阳时 23:00」，不是北京时 23:00。

以某西部城市（经度约 **110.8°E**）为例：与 120°E 差约 9.2°，再加均时差，真太阳时 ≈ 北京时 − 49 分上下。于是：

- 真太阳时 23:00 ⇔ 北京时约 **23:49**
- 北京时 23:49 ⇔ 真太阳时约 **22:59（亥时）**，距真太阳时日界仅二十余秒

**结论**：在这类城市，真太阳时的「换日边界」恰好落在北京时 23:49 附近。故同一时刻：

| 取法 | 结果 |
|---|---|
| A. 真太阳时校正 + 日界在真太阳时 23:00（或软件默认晚子时算当日） | 真太阳时约 22:59 = 亥时 → **当日**日柱 |
| B. 日界在 23:00 北京时 / 紫微式晚子时归次日（不对晚子时做真太阳时校正） | 北京时 23:49 = 子时 → **次日**日柱 |

两派**几乎重合于边界**。**但本技能已由第〇节之准则一次裁定（归次日），不再悬置。**
下方两派对照表仅作技法备查之用。

## 三、万年历校验方法（本技能即此实现，并非缺万年历）

本技能用 `lunar-typescript`（`paipan.js` 依赖）做公历↔干支换算，已具备完整万年历能力；错误不在「无历」，而在「未显式处理换日流派」。`paipan.js` 默认采用流派一（晚子时算当日）。

**取次日日柱的实操**：直接以次日日期排盘即可（示例为虚构）：

```bash
cd <skill>/scripts
export NODE_PATH=<bin>/node/workspace/node_modules
N=<bin>/node/versions/<版本>/bin/node
$N paipan.js chart "1990-05-16 00:10" 1
```

**已校验锚点**（与 `lunar-typescript` 一致，任何人可复算）：

- 2000-01-01 → **戊午**日
- 2026-01-01 → **乙亥**日
- 1984-02-04 → **戊辰**日（当日立春）

> 用法：拿这几个锚点先验证你的排盘工具链是否与万年历一致，再动真实命例。

## 四、报告纪律（强制，已按第〇节准则改写）

1. 凡出生时间落在 **23:00–24:00**，**一律按第〇节准则判为「归次日」**，并**在报告开头显式写出裁决过程**：
   「一天只有一个子时；23:55 已过 23:00，属第二个子时，故日柱归次日。」
2. 报告须**写明本报告采用的日柱与日主**，并说明**为何必须裁准**（点出日主之差会连带改写时柱、调候、
   用神、相神、大运）。
3. **裁决之后即定论**：全篇**不得再出现「若为某柱则…、若为另一柱则…」的悬置表述**。
   读者的最大确定性来自「一个明确的结论」，而非「两个并列的可能」。
4. 另一派之盘**最多在附录列一张对照表**（备日后回溯），**不计入正文推演**。
5. 仅当**用户明确要求双派并列**时，才走「四之二」的双盘解法。
6. **技术陷阱必读**：`paipan.js` / `lunar-typescript` 的**默认**是「晚子时算当日」（流派一），
   **与本技能立场相反**。故晚子时命例**必须显式改用「次日日期」排盘**，
   并以「次日 00:10 排盘应得同一日柱」做自洽性复核。

## 四之二、双盘解法：先提「骨架不变量」，再谈分歧（**仅当用户明确要求双派并列时使用**）

> **前置**：按第〇节准则，本技能**默认已裁决为「归次日」**，正常情况下**不需要**走本节的四步法。
> 本节仅在两种情形下启用：① 用户明确要求双派并列；② 该命例的日界分歧**可能改变骨架**
> 而用户希望看到两种结论。
>
> 若确需双盘，切忌把两个盘**平铺并列**、逐项对照——那样报告里到处是
> 「若为甲则…、若为乙则…」，读者读完仍不知结论。**正确做法是先做减法。**

**四步法**：

1. **先各排一盘**（`paipan.js chart "<datetime>" 1` 取流派一；流派二按"次日同时刻"再排一盘）。
2. **提取骨架不变量**——只看这七项，逐项比对是否两盘相同：

   | 序 | 不变量项 | 说明 |
   |---|---|---|
   | 1 | 月令与格局 | 财/官/印/食等八格归属 |
   | 2 | 调候主神之有无 | 该月令所须的调候干，在**四柱中是否存在** |
   | 3 | 用神／相神 | 取用与相神是否落同一五行 |
   | 4 | 旬空之支 | 两盘旬空位置及所伤之十神 |
   | 5 | 天干层关系 | 干五合／相冲／争合 是否同 |
   | 6 | 日主之根 | 日主在支中是否得根、是否自坐禄刃 |
   | 7 | 大运干支 | 起运岁数若接近，首二三步运是否同干支 |

3. **不变量内的结论，直接下，不留口子。** 骨架 7 项中**相同**的项，其推出的结论在两派下
   都成立，报告**照写即可**，不必加「若…则…」。
4. **只在骨架分歧处**（通常是第 1、5、6 项被改变时）才启动第四节的流派裁决，且**分歧单列成表**。

**判据**：若骨架 7 项全同，则**结论不依赖日界取舍**——此时应在总说明中明写这句话，
这是给读者的最大确定性，也是本技能质量的分水岭。

**示例（虚构）**（某造生于 `1995-08-20 23:55`，真太阳时校正后落于子时）：
A 盘（归次日）`乙亥 甲申 **甲申** 甲子` / B 盘（算当日）`乙亥 甲申 **癸未** 甲子` ——
两盘**年柱、月柱（月令申、格局之源）与大运干支、起运完全相同**，属**骨架不变量**；
分歧只在**日柱（日主甲／癸）**，而**时干由日干起**，故时柱（甲子／甲子）、
调候主神有无、用神与相神随日主而变。
→ **不依赖日主五行**的结论两盘通用，可直接下；**涉及日主的**（用神、相神、调候主神）
须先按第〇节裁决日柱再落笔，不得并列悬置。
（复算：`paipan.js chart "1995-08-21 00:10" 1` 与 `paipan.js chart "1995-08-20 23:55" 1`。）

## 四之三、附带纪律：起运极晚的命

若起运岁数 ≥ 6 年（交运在 6 岁后），则该命**在交运前只论流年，不排大运评分**。
报告须显式声明「某年至某年不排大运评分，仅论流年」，否则会给出对命主毫无意义的运评分，
属硬伤。（本技能实测：有起运迟至 9 岁前后才交运者，交运前一律只论流年、不排大运评分。）

## 五、快速判定表（按第〇节准则，常用出生段）

| 出生北京时 | 真太阳时（约 110.8°E 城市示例） | **本技能裁决（归次日）** | 排除的日柱（旧两派之另一说） |
|---|---|---|---|
| 22:40 | 21:51（亥） | —— **不属子时，无需裁决** | —— |
| 23:30 | 22:41（亥） | **不属子时**（真太阳时未到 23:00）——但**北京时已过 23:00，仍判归次日** | 当日 |
| 23:49 | 22:59（亥，距界约 20 秒） | **归次日**（北京时已过 23:00） | 当日 |
| 23:55 | 23:02（子） | **归次日** | 当日（本技能不采） |
| 00:10 | 23:20（前一日子） | **归次日**（本即次日） | 当日 |

> **注**：本技能以**「北京时是否已过 23:00」**为判据（即「是否出现第二个子时」），
> 而非以真太阳时是否到 23:00 为判据。故 23:30 这类「北京时已过 23:00、真太阳时仍属亥」的时刻，
> 仍判**归次日**——因准则的表述是「第二个子时」，以钟表时刻为准。
> 若用户另有指定，从其指定。
